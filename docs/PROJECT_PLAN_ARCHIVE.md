## 1. 원래 제품 비전

- PC 1280×720, Godot 4.7+, 2D 픽셀 아트 내러티브 어드벤처
- 주인공은 예수를 처음부터 아는 제자가 아니라 예루살렘의 이름 없는 일반 시민이다.
- 플레이어는 영웅의 회고가 아니라 군중 속에서 직접 걷고, 소문·증언·흔적을 비교한다.
- 기본 루프는 `이동 → 흔적/인물 조사 → 서로 다른 관점 발견 → 다음 장소 개방`이다.
- WASD/방향키 8방향 이동, E 조사, Space 대화 진행, 월드 스페이스 말풍선을 사용한다.
- 역사적 사건은 바꾸지 않는다. 플레이어의 관찰과 도움·거리 두기·침묵 같은 반응만 후속 대사와 에필로그 회상에 남긴다.
- 예수님과의 직접 대화는 드물고 짧게 유지한다. 제목의 “열세 번째 제자”는 실제 사도 직함이 아니라 마지막에 플레이어에게 돌아오는 질문이다.
- 결말은 신앙의 정답을 채점하지 않는다. 본 것·들은 것·추론한 것을 구분하고 열린 질문을 남긴다.

## 2. 초기 공통 시스템 계획

- 장별 데이터를 `story_data.gd`와 `ChapterDefinition`으로 분리한다.
- `ChapterDirector`, `WorldChapterBase`, `StoryState/GameState`가 장 전환·완료 조건·저장·마이그레이션을 담당한다.
- 메뉴, 장면 선택, 설정, 텍스트 속도, 글자 크기, 오디오 버스를 공통화한다.
- 대화와 상호작용은 신호 기반 컨트롤러로 분리하고, 기존 코드는 새 컨트롤러가 검증될 때까지 보존한다.
- 장 재방문은 도입부터 시작하되, 이미 기록한 관찰·선택은 저장한다. 선택 결과가 에필로그에 반영되도록 한다.
- 카메라는 부드럽게 추적하되 정수 픽셀에 정렬하고, 2048×720 월드 밖을 노출하지 않는다.
- 자동 검증은 씬 로드, 스토리, 컷신, 입력 잠금, 일시정지, 실제 이동, 장별 플레이스루와 저장 보존을 포함한다.

### 계획에 사용하기로 한 스킬과 도구

초기 채팅에서 추천·적용 대상으로 정리된 능력은 `game-dev`, `godot-gdscript-patterns`, `godot-2d-movement`, `godot-ui`, `godot-camera-systems`, `godot-audio-systems`/`audio-design`, `pixel-art-sprites`, `imagegen`이다. 용도는 각각 Godot 게임 구조, 이동·충돌, UI·입력, 카메라·픽셀 정렬, 오디오 버스·덕킹·발소리, 스프라이트·팔레트, 배경·캐릭터 생성이다.

현재 작업에서는 Godot 관련 코드·테스트 지침과 아트 디렉션을 적용했다. `imagegen`은 깨끗한 배경 교체를 시도했으나 사용량 제한으로 새 최종 배경을 만들지 못했으므로, 캡처 기반 fallback을 최종 원본으로 승격하지 않는다.

## 3. 제1장 계획 · 군중 속의 낯선 사람

목표는 한 방향으로 몰린 군중이 누구를 기다리는지 확인하는 것이다. 시장 쪽에서 시작해 종려잎, 버려진 겉옷, 성문을 향해 모이는 발자국 세 흔적을 조사하고 요나·미리암의 서로 다른 관점을 듣는다.

초기 채팅에서 확정한 세부 사항:

- 종려잎은 환영과 왕적 상징이므로 치우는 장애물로 만들지 않는다. 길에 놓고, 밟힌 뒤 남은 흔적을 읽는다.
- 겉옷도 길에서 제거해 사건을 되돌리지 않는다. 주인과 먼지·발자국을 살핀다.
- 예수님과 나귀의 등장은 오른쪽 돌담을 넘는 우회가 아니라 오른쪽 샛길의 안전한 길 중심을 따라야 한다.
- 캐릭터의 발 기준점과 실제 스프라이트 폭을 함께 고려하고, NPC와의 최소 간격·충돌선을 회귀 테스트한다.
- 말풍선은 카메라 변환 후 캐릭터의 명시적인 머리 앵커를 사용해야 한다.
- 세 흔적 뒤 짧은 조우와 자유 탐색을 제공하고, 주민 의견은 선택적으로 듣되 2장 진행을 막지 않는다.
- 발소리는 실제 이동 거리와 보행 프레임에 맞춰 재생하고, 막힌 상태에서는 발소리·보행을 멈춘다.
- Kenney CC0 발소리와 조사별 Foley를 사용하고, 최종 헤드폰/스피커 믹스는 별도 청취한다.

## 4. 제2장 계획 · 성전의 소음

초기에는 `직접 본 것/들은 것/해석한 것`을 버튼으로 분류하는 모달 퀴즈와 증거 연결 카드가 제안되었지만, 채팅에서 퀴즈 감각과 성경 맥락 충돌을 확인한 뒤 폐기했다.

최종 의도는 “사건을 되돌리는 정답”이 아니라 “사건 뒤의 공간과 사람을 돌보는 행동”이다.

- 흩어진 동전: 상 위에 되돌려 놓지 않고, 발에 밟히지 않게 천 위에 하나씩 모은다.
- 뒤집힌 상: 다시 세워 장사를 복구하지 않는다. 통로 가장자리로 밀어 기도 공간을 드러낸다.
- 기도 자리: 새로운 의미를 발명하지 않고 접혀 있던 천을 펼쳐 다시 사용할 수 있게 한다.
- 요나·미리암·성전 경비는 플레이어가 실제로 한 행동 뒤에 반응한다. NPC가 정답을 말하지 않는다.
- 상호작용 동사는 장면의 의미에 맞게 줍기·밀기·펼치기·건네기처럼 구분한다.
- 2장의 물리 목표는 장식 플래그가 아니라 실제 통로가 열리고 플레이어가 지나갈 수 있는 상태여야 한다. 물건을 들었다가 `R`로 출처에 돌려놓을 수 있어야 한다.

과거의 One Dreamer 참고 계획은 공통 원칙으로 보존한다: 플레이어가 요소를 실행하고 결과를 관찰한 뒤 다시 수정하는 감각. 현재 구현은 이를 직접적인 코드 편집 UI가 아니라 현장 조사·배치·운반·NPC 반응으로 번역한다.

## 5. 제3장 계획 · 기다림 뒤에 남은 발소리

- 같은 2048×720 우물가를 늦은 오후 → 해질녘 → 밤으로 변화시킨다.
- 우물, 접힌 천·물그릇, 미리암과 선택 증언을 순서 제한 없이 조사한다.
- 부서진 등불, 기름 자국, 끌린 흔적, 버려진 샌들을 통해 체포 행렬의 경로를 추적한다.
- 등불을 실제로 들고 배치·회전하며, 벽에 가려진 빛은 보이지 않게 한다. 밝혀진 흔적과 먼 횃불을 비교해 목적지를 찾는다.
- `H`는 진행을 초기화하지 않는 단계별 힌트다. 잘못된 방향·취소·재개·나가기 취소 후 입력 복구를 보장한다.
- 최종 행동은 소리를 따라감, 거리를 두고 지켜봄, 달아나는 청년을 도움의 세 가지이며, 각 행동은 저장·에필로그 회상에 연결된다.
- 목표 플레이 시간은 강제 대기로 늘리지 않고 실제 탐색·독서 속도·추가 서사 필요량으로 사람에게 측정한다.

## 6. 제4~6장과 에필로그 계획

### 제4장 · 서로 다른 외침

화톳불, 닫힌 문, 군중의 메아리를 조사해 한 사람의 말이 군중 속에서 어떻게 단정적인 외침으로 증폭되는지 걷고 듣는다. 플레이어는 본 범위를 말하기, 침묵하기, 군중에서 떠나기를 선택한다. 베드로의 부인 뜰과 빌라도 재판장은 구분한다.

### 제5장 · 끝까지 바라본 사람들

십자가의 길과 골고다 아래에서 빈 물그릇, 밀려난 천, 침묵하는 목격자를 조사한다. 물그릇을 놓기, 혼자 선 사람 곁에 서기, 멀리서 끝까지 바라보기를 선택한다. 처형을 직접 묘사하지 않고 바람, 어두워지는 하늘, 떠나는 군중으로 무게를 전달한다.

### 제6장 · 빈자리의 증언

시장 소문, 막달라 마리아의 증언, 옮겨진 돌과 빈 무덤을 조사한다. 직접 본 것·전언·추론을 구분하되 `믿음`을 정답으로 채점하지 않는다. 신뢰하기, 증거가 더 필요함, 열린 채 남기의 세 태도를 기록한다. 부활은 동등한 소문 중 하나로 축소하지 않으며, 본문 근거와 창작 연결을 분리한다.

### 에필로그

1장의 흔적과 2~6장의 저장된 행동을 짧게 회상하고, 열린 질문과 크레딧으로 마무리한다. 저장된 선택이 보이되 어느 선택도 정답·오답으로 표시하지 않는다.

## 7. 성경 기준 개편 계획

- 사건 순서는 입성 → 성전 → 유월절 식사·겟세마네 → 심문 → 빌라도 재판 → 십자가 → 장사 → 빈 무덤을 따른다.
- 긴 본문 설명 대신 인물 이동, 횃불, 식탁, 체포, 재판장 이송, 십자가 행렬, 어두워지는 장면, 장사와 열린 무덤을 짧은 컷신으로 연결한다.
- 예수님에게 새로 만든 질문·설명 대사를 부여하지 않는다. 현장에서는 짧은 등장, 타인의 증언, 플레이어의 반응으로 거리를 유지한다.
- 주인공·요나·미리암은 창작 인물이며, 성경 인물의 정체·사건 결과와 명확히 구분한다.
- 6개 장에 총 39개 현장 행동을 배치한다. 걷기, 조사, 운반, 배치, 밀기, 등불 방향 조절을 실제 월드에서 수행한다.
- 막달라 마리아, 요나, 미리암 등 반복 인물은 동일한 continuity id와 외형을 유지하고, 장면별 단역은 다른 자산을 사용한다.

## 8. 아트·오디오·프레젠테이션 계획

- 배경은 `ART_DIRECTION.md`의 2048×720 RGB, 3/4 탑다운, 하단 보행 영역, 좌상단 따뜻한 광원, 황토·사암·남보라 팔레트를 따른다.
- Nearest와 정수 배율을 유지한다. 48–64색 목표, 수작업 픽셀 검수, 알파 가장자리 검수를 별도로 한다.
- 배경에는 UI, 플레이어, 중요 NPC, 조사물, 움직이는 문·물체를 굽지 않는다. 모두 별도 투명 리소스와 노드로 배치한다.
- 새 배경은 좌·중·우 카메라와 16:10 창에서 랜드마크·보행로가 잘리는지 확인한다.
- 캐릭터는 방향별 보행·정지 애니메이션, 발 기준점, 일관된 의상·색을 사용한다. 플레이어 4프레임은 연결됐지만 주요 NPC 전체 확장은 별도 작업이다.
- 오디오 버스는 Master/Ambience/SFX/UI/Dialogue를 사용하고, 대화 중 환경음 덕킹·거리 감쇠·조사별 Foley를 유지한다. 최종 청취는 자동 테스트와 분리한다.

## 11. SecondBrain에서 가져온 개발 운영 원칙

- “완료”를 구현, 검증, 전달로 나눠 기록한다. 미커밋 작업은 출시된 기능처럼 표현하지 않는다.
- 테스트 수는 실행한 검사의 결과일 뿐, 실제 사용자 흐름을 대신하지 않는다.
- 대표 흐름 `조사 → 저널 → 일시정지/재개 → 저장/재시작 → 다음 장`을 처음 하는 사람에게 직접 확인하고 막힌 지점을 기록한다.
- 공통 런타임 경계를 바꿀 때 어떤 중복·오류를 줄였는지 실제 사례 하나를 남긴다.
- 문제 해결 뒤 `상황/원인 → 선택한 해결책과 근거 → 다른 프로젝트에 적용할 조건`을 기록해 다음 작업에 재사용한다.
